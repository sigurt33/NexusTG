# 📘 Полное руководство пользователя — NexusTG

Локальный агрегатор Telegram-задач. Собирает из всех твоих чатов сообщения, требующие внимания (ЛС, упоминания, ответы на твои сообщения), классифицирует их через Gemini, расставляет приоритеты и показывает в веб-инбоксе + шлёт в Telegram-бот.

---

## Свежие обновления (2026-06-02)

- **Listener: периодический ре-синк чатов** — каждые 5 минут `sync_chats` + перечитывание `archived_chat_ids` и `processing_off`. Раз-архивирование чата или включение processing подхватывается без рестарта `run.ps1`.
- **Логирование пропусков reply-to-me** — если `get_reply_message()` упал, в лог пишется `warning` с chat_id/msg_id вместо тихого пропуска.

## Свежие обновления (2026-05-31)

- **📋 Шаблоны** (`/templates`) — заготовки быстрых ответов: создавай/редактируй/удаляй; доступны в карточке сообщения через выпадающее меню.
- **💬 Быстрый ответ** в карточке `/message/{id}` — кнопка открывает поле, текст уходит в Telegram как `reply_to` на оригинал. Работает через `outbox` (web кладёт в БД, `outbox_sender` в `run.ps1` отправляет за 3-5 сек).
- **✓ Выполненные** (`/done`) — архив всех «Готово» с кнопкой ↩ Вернуть в инбокс.
- **⚙️ Алина-режим** (`/rules`) — правила свободным текстом, подмешиваются в системный промт классификатора.
- **🎨 Цветовая палитра** в шапке — 4 схемы (розовая / зелёная / сиреневая / синяя), кнопки + бейджи + ссылки + фоны меняются глобально.
- **🌙 Тёмная/светлая тема** — переключатель в шапке, сохраняется в localStorage.
- **👤 Аватар + ник** Telegram-аккаунта справа в навбаре, обновляется при старте.
- **⌨️ Шорткаты** в инбоксе: `j/k` навигация, `e` готово, `s` snooze, `a` архив, `o/t` открыть, `/` поиск, `?` подсказка.
- **🧠 Neural-фон** — анимированная сеть из ~220 точек, светлая/тёмная подстраиваются.
- **🔁 Фильтр ботов** — все сообщения от ботов (включая нашего) автоматически пропускаются.
- **📦 Migration toolkit** — `migrate.ps1` упаковывает проект в zip для переноса, `requirements-windows.txt` как pip-fallback, `setup.ps1` спрашивает про существующую сессию.
- **NexusTG** — ребрендинг с aichatpom, видео-логотип в шапке, favicon.

## 1. Что это и зачем <a name="что-это-и-зачем"></a>

У тебя ~40 групп в Telegram + ЛС. Каждый день в них летят сотни сообщений, из которых только малая часть требует ТВОЕЙ реакции: тебя упомянули, ответили на твоё сообщение, написали в ЛС. Остальное — фон.

NexusTG:
- **Собирает** только релевантное (3 правила: ЛС, упоминания @твой_username, ответы на твои сообщения)
- **Понимает контекст** — вокруг каждой задачи сохраняет ±5 соседних сообщений из того же чата
- **Классифицирует** через LLM Gemini 2.5 Flash: тема (автоматически растущая таксономия) + срочность 1-5 + важность 1-5
- **Сортирует** по итоговому score = urgency·0.6 + importance·0.4
- **Показывает** в веб-инбоксе (localhost:8000) и шлёт в твой Telegram-бот
- **Учится** на твоих правках через примеры и правила («Алина-режим»)

Архивные чаты Telegram пропускаются автоматически.

## 2. Первый запуск <a name="первый-запуск"></a>

### 2.1 Что должно быть установлено
- Windows 11
- Python 3.12+
- uv (менеджер окружения): `winget install astral-sh.uv`

### 2.2 Конфиги
В `.env` (в корне проекта):
```
TG_API_ID=...        # с https://my.telegram.org → App api_id
TG_API_HASH=...      # оттуда же
XAI_API_KEY=...      # Gemini ключ с https://aistudio.google.com/apikey
TG_BOT_TOKEN=...     # бот от @BotFather (опционально, для бот-режима)
TG_MY_ID=...         # твой числовой Telegram ID (@userinfobot покажет)
```

В `config.toml` — настройки, основные:
- `timezone = "Europe/Minsk"` — твоя зона
- `active_hours_start = "10:00"` / `active_hours_end = "18:30"` — окно уведомлений
- `grok_model = "gemini-2.5-flash"` — модель LLM
- `grok_daily_token_budget = 8000000` — дневной лимит токенов
- `notify_windows_toast = true` / `notify_tg_self = true` / `notify_tg_bot = false`

### 2.3 Авторизация Telegram
```powershell
cd C:\Users\User\ClaudeC\NexusTG
.\setup.ps1
```
Запросит телефон (с `+375`) и код подтверждения. Код приходит в TG-приложение в чат «Telegram» (НЕ SMS). Если стоит двухфакторка — попросит облачный пароль TG.

После успеха создаётся `data/tg.session`.

### 2.4 Первый запуск конвейера
```powershell
.\run.ps1
```
Это запустит:
- **Backfill 30 дней** — пройдётся по всем неархивным чатам, заберёт сообщения за последний месяц по 3 правилам
- **Realtime listener** — подписка на новые сообщения
- **Classifier worker** — каждые 10 сек берёт необработанное, шлёт в Gemini
- **Notifier** — копит/шлёт уведомления
- **Telegram-бот** (если `TG_BOT_TOKEN` задан)

Backfill 30 дней по 450 чатам = ~30 минут. Можно параллельно открыть веб:
```powershell
# второе окно PowerShell
.\web.ps1
```
Открой **http://127.0.0.1:8000**.

## 3. Ежедневное использование <a name="ежедневное-использование"></a>

Обычный день:
1. Утром в 10:00 в Telegram прилетает сводный дайджест: «N новых задач за нерабочее время. Топ: ...»
2. Открываешь **http://127.0.0.1:8000** — инбокс отсортирован по приоритету
3. Сверху самое горячее (красный score 4-5). По каждому: ✅ Готово / 💤 Отложить / 📦 Архив
4. Новые задачи в течение рабочего дня прилетают:
   - Windows toast (правый нижний угол) — клик открывает карточку в браузере
   - Сообщение от бота в Telegram с инлайн-кнопками
5. Вечером в `/digest` можно глянуть итоги дня. В `/reports/weekly` — за неделю.

Чтобы пайплайн крутился непрерывно — оставь окно с `run.ps1` открытым. После ребута Windows — запустить заново.

## 4. Веб-дашборд: каждая страница <a name="веб-дашборд"></a>

### 4.1 `/` Инбокс
Главная страница. Список активных задач, отсортированных по score.

**Фильтры сверху:**
- Все источники / ЛС / Упоминания / Ответы
- Чат (выпадающий список)
- Тема
- Текст содержит (live-поиск с debounce)
- Чекбокс «Показать неклассифицированные» — иначе скрываются те, что ещё ждут классификатора

**Каждая строка:**
- Бейджи слева: `ЛС`, `@`, `↩`, `💤` (если отложено)
- Чат, отправитель, чипы тем
- Сниппет текста (220 символов)
- Кнопки действий: ✓ Готово / 💤 Отложить (1ч / Завтра 10:00 / Понедельник 10:00 / Своё) / 📦 Архив
- Справа: score, U/I (срочность/важность), относительное время

Клик по строке — карточка сообщения.

**Шорткаты в верхнем правом углу** (раскрывающаяся подсказка с таблицей клавиш).

### 4.2 `/message/{id}` Карточка сообщения
- **Сам контекст ±5** — окно разговора: 5 сообщений до целевого + 5 после. Целевое выделено жирной полосой слева.
- **Темы**, urgency, importance, rationale (объяснение LLM почему такая оценка)
- **Кнопки:**
  - ✓ Готово / 💤 / 📦 — те же что в инбоксе + ↩ Вернуть в инбокс
  - 🔁 **Переклассифицировать** — удалить старые темы/приоритет, прогнать заново через Gemini (учтёт новые правила/примеры)
  - 🌐 **Открыть в Telegram** — deep-link `tg://openmessage?chat_id=...` (открывает desktop-TG на нужном сообщении)
  - ⭐ **Сохранить как пример** — пометить этот результат как эталон; будет подмешиваться в промт для будущих классификаций
- **Inline-редакция urgency/importance** — селекты 1-5, сохраняет сразу
- Бейдж «⭐ Эта оценка — пример для обучения», если уже сохранена

### 4.3 `/search` Поиск
Полнотекстовый поиск по всем сообщениям (FTS5 SQLite). Подсветка совпадений. Debounce 400мс. Ищет по тексту, имени чата, имени отправителя.

### 4.4 `/topics` Темы
Две вкладки:
- **Список** — плоская таблица всех видимых тем. Колонки: ID, slug, label_ru, описание, количество сообщений, дата создания.
  - Кнопки на каждой теме: Переименовать, Скрыть, Назначить родителя, История сообщений
  - Внизу — **массовый merge**: чекбоксы → выбрать целевую тему → объединить
- **Иерархия** — древо родитель→дети (если назначены parent_id)
- **Скрытые** — раздел внизу с возможностью вернуть тему обратно

Клик на название темы → страница всех её сообщений с возможностью убрать тему у конкретного сообщения.

### 4.5 `/digest` Дайджест
Сводка за вчера: топ-20 задач по score, сгруппированные по основной теме.

### 4.6 `/reports` Отчёты
Лендинг с тремя картами:
- **За неделю** — гистограмма по дням, топ-10 тем, топ-5 чатов, топ-5 отправителей
- **По темам** — таблица: тема, кол-во за всё время / 7д / 30д, средний score, последняя активность
- **По чатам** — аналогично по чатам
- **По отправителям** — кто чаще всего пишет

`/export/messages.csv?from=&to=&topic=&chat=&min_score=` — CSV-выгрузка для Excel (UTF-8 BOM, `;` разделитель).
`/export/topics.csv` — все темы CSV.

### 4.7 `/chats` Чаты
Список ВСЕХ твоих диалогов TG. Колонки: title, последняя активность, кол-во захваченных сообщений, флаг архивности, флаг «обработка».

Действия:
- Переключатель **«Обрабатывать да/нет»** на каждый чат — если выключить, classifier перестанет тратить токены на этот чат и он исчезнет из инбокса. Сообщения уже захваченные остаются в БД.
- Кнопка **«Синхронизировать с Telegram»** — обновляет список (новые чаты, изменения архивности) — нужна когда в TG что-то заархивировал/разархивировал.

### 4.8 `/examples` Примеры
Все сохранённые ⭐ примеры. Можно редактировать заметку (зачем именно этот пример), удалять. Примеры подмешиваются в системный промт классификатора (последние 5).

### 4.9 `/rules` Алина-режим (Правила)
Свободный текст-правила, влияют на классификацию. См. раздел 7.

### 4.10 `/health` Здоровье
Состояние сервиса: всего сообщений, классифицировано, последний classified_at, лаг ingest, расход токенов сегодня + стоимость, прогресс backfill.

## 5. Telegram-бот <a name="telegram-бот"></a>

Если `TG_BOT_TOKEN` и `TG_MY_ID` заданы в `.env` — при `run.ps1` запускается отдельный бот.

### Команды
- `/start` — приветствие
- `/inbox` — топ-10 активных задач с кнопками
- `/digest` — сводка за вчера
- `/help` — список команд

### Инлайн-кнопки под каждой задачей
- ✅ **Готово** — пометить выполненной
- 💤 **1 ч** — отложить на час
- 🌅 **Завтра 10:00** — отложить до завтра утра
- 📦 **Архив** — заархивировать
- 🌐 **Открыть** — кнопка-URL, ведёт на `http://127.0.0.1:8000/message/{id}`

После нажатия кнопок: бот редактирует сообщение, добавляя строку «✓ Готово · 14:32» и убирает клавиатуру. Действия пишутся в ту же таблицу `user_actions` что и веб — синхронизация автоматическая.

### Автонотификации
Watcher каждые 30 сек ищет новые классифицированные задачи со `score ≥ 3.0` и шлёт их в бот. В нерабочее время — копит в `pending_notifications` и в 10:00 присылает один сводный апдейт.

### Whitelist
Бот принимает команды ТОЛЬКО от `TG_MY_ID` (твой числовой ID). Левые люди, нашедшие бот, получат отказ.

## 6. Клавиатурные шорткаты <a name="клавиатурные-шорткаты"></a>

Работают на странице инбокса когда курсор НЕ в поле ввода.

| Клавиша | Действие |
|---|---|
| `j` / `k` | следующее / предыдущее сообщение (фокус подсвечивается) |
| `g` / `G` | в самое начало / в самый конец списка |
| `e` | пометить «Готово» |
| `s` | отложить на 1 час |
| `a` | в архив |
| `o` | открыть карточку (та же вкладка) |
| `t` | открыть карточку в новой вкладке |
| `/` | фокус на поиск |
| `Esc` | выйти из поля ввода обратно в режим шорткатов |
| `?` | открыть/закрыть подсказку |

После действия (e/s/a) HTMX удаляет строку, фокус автоматически встаёт на следующую — можно прокликать инбокс не отрывая руки от клавиатуры.

## 7. Алина-режим (правила) <a name="алина-режим"></a>

Адрес: `/rules`.

Свободный текст. Подмешивается в системный промт классификатора в секцию `ПРЕДПОЧТЕНИЯ ПОЛЬЗОВАТЕЛЯ`.

### Примеры рабочих правил
- «Сообщения от родителей школы (чат „Детские преподаватели") — это важно (importance ≥ 4).»
- «Любые упоминания денег, оплат, инвойсов — urgency ≥ 4.»
- «Если в чате обсуждение мемов или флуд — urgency = 1, importance = 1.»
- «SlavaLevch — мой ключевой партнёр, его сообщения = importance ≥ 4.»
- «Тему „Доходы школы" используй только если речь о конкретных суммах.»
- «Если в сообщении есть слово „срочно" или „надо сегодня" — urgency = 5.»

### Управление
- Добавить новое — большое текстовое поле + кнопка ➕ Добавить
- 💾 Сохранить — изменить текст существующего
- 🚫/✅ Выключить/Включить — временно отключить без удаления
- 🗑️ Удалить — навсегда (с подтверждением)
- Бейдж ВКЛ/ВЫКЛ зелёный/серый

### Когда правило начинает работать
Сразу — со следующей классификации. На уже классифицированные сообщения не влияет. Чтобы пересчитать старое сообщение — открой его и нажми **🔁 Переклассифицировать**.

### Стратегия использования
Начни с 2-3 правил. Поработай пару дней — посмотри как Gemini реагирует. Затем доточи. Не пиши конфликтующие правила (Gemini выберет одно и проигнорит другое). Чем конкретнее — тем лучше.

## 8. Темы, теги, иерархия <a name="темы"></a>

Темы создаются автоматически: Gemini получает список существующих и либо выбирает 1-3 подходящих, либо предлагает новую (с slug + label_ru + описание). Новые темы фильтруются через rapidfuzz: если label похожа на существующую (token_set_ratio ≥ 85) — переиспользуем старую.

### Когда чистить
- Раз в неделю заходи на `/topics` → смотри список → синонимы объединяй через merge
- Мусорные темы (по 1-2 сообщения, неинформативные) — кнопка «Скрыть»
- Скрытые темы можно вернуть из раздела «Скрытые» внизу страницы

### Иерархия
Можно назначать родителя теме (например, «Финансы школы» → родитель «Финансы»). На вкладке «Иерархия» показывается древом. Для классификатора иерархия пока не влияет на промт — это чисто для твоей навигации.

### Ночной consolidator
В 03:00 локально запускается job, который:
- Помечает темы со счётчиком <3 за 30 дней как hidden (если они старше 14 дней)
- Логирует подозрительно похожие пары в `data/logs/merge_suggestions.log` (без автомержа — решаешь сам)

## 9. Действия с задачами <a name="действия"></a>

| Действие | SQL запись | Эффект |
|---|---|---|
| ✓ Готово | `user_actions(action='done')` | Сообщение исчезает из инбокса навсегда |
| 💤 Отложить 1ч | `action='snoozed', snooze_until=now+1h` | Исчезает; через час возвращается + уведомление |
| 💤 Завтра 10:00 | `snooze_until=завтра 10:00 Europe/Minsk` | Возврат завтра утром |
| 💤 Понедельник 10:00 | `snooze_until=ближайший пн 10:00` | Откладывание на выходные |
| 💤 Своё | произвольная дата | Через datetime-local picker |
| 📦 Архив | `action='archived'` | Спрятать без пометки выполненным |
| ↩ Вернуть | `action='unread'` | Отмена done/snooze/archive — вернуть в инбокс |

Snooze sweeper в фоне (каждые 60 сек) переводит истёкшие snoozed → unread и фаерит уведомления.

## 10. Поиск <a name="поиск"></a>

`/search` — SQLite FTS5 по `messages_fts(text, chat_title, sender_name)`.

- Tokenizer: `unicode61 remove_diacritics 2` — нечувствителен к ё/е, ударениям
- Ranking: `bm25()` (релевантность важнее свежести)
- Подсветка: `<mark>...</mark>` в snippet
- Поддерживаются wildcard'ы: к каждому слову автоматически добавляется `*` (поиск по подстроке)
- Кириллица работает полностью

Чтобы искать конкретного человека: пиши его имя или username. Чтобы по конкретному чату — пиши название чата.

## 11. Отчёты и экспорт <a name="отчёты"></a>

### Регулярная польза
- `/reports/weekly` каждое воскресенье — посмотреть кто/что чаще всего висело в инбоксе. Можно понять что неэффективно (например, чат шлёт много низко-важного — выключить обработку через `/chats`).
- `/reports/topics` — выявить темы которые редко возникают и доминирующие.
- `/reports/chats` — топ-чаты по объёму захваченных задач.

### CSV-экспорт для Excel/анализа
```
GET /export/messages.csv?from=2026-05-01&to=2026-05-30&topic=finance&min_score=3.0
```
Параметры все опциональные. UTF-8 BOM → Excel сразу читает кириллицу. Разделитель `;`.

Поля: id, дата, чат, отправитель, текст, score, urgency, importance, темы (через запятую), действие пользователя.

## 12. Управление чатами <a name="управление-чатами"></a>

`/chats` — таблица всех твоих диалогов.

### Архивные чаты
Когда в Telegram свайпом отправляешь чат в Архив — на следующем `run` (или после `sync-chats`) у нас в БД ставится `archived=1` и:
- Classifier перестаёт тратить токены на этот чат
- Инбокс перестаёт показывать
- Backfill пропускает

### Allow/block list — флаг `processing`
Кроме архива, можно вручную выключить обработку любого чата кнопкой «Выключить обработку». Например: рабочий чат, где тебя часто упоминают, но это всегда мусор. Сообщения продолжат приходить в Telegram, но в инбокс не попадут.

### Синхронизация
Чтобы подхватить новые чаты или изменения архивности в TG — нажми «🔄 Синхронизировать с Telegram». Альтернатива из CLI:
```powershell
uv run python -m app.cli sync-chats
```

## 13. Уведомления <a name="уведомления"></a>

Включаются для задач со **score ≥ 3.0** (примерно urgency≥3 или importance≥4).

### Три канала (можно использовать вместе или по отдельности)
- **Windows toast** (config: `notify_windows_toast`) — всплывающее окно в правом нижнем углу. Клик открывает карточку в браузере.
- **Self-ping в Saved Messages** (config: `notify_tg_self`) — твой собственный Telegram-аккаунт шлёт сообщение в чат «Saved Messages» через MTProto-сессию.
- **Telegram-бот** (config: `notify_tg_bot` + `TG_BOT_TOKEN`) — отдельный бот шлёт с инлайн-кнопками действий.

### Активные часы
`active_hours_start` / `active_hours_end` в `config.toml` (по умолчанию 10:00–18:30 Europe/Minsk).

**Вне активных часов:** уведомления НЕ показываются, копятся в `pending_notifications`.

**При наступлении active_hours_start утром:** прилетает ОДИН сводный апдейт «N новых задач за нерабочее время. Топ: ...» — туда же куда обычные нотификации.

### Что делать с уведомлением
Toast: клик → открывается карточка задачи.
Telegram-бот: нажми ✅/💤/📦/🌐 прямо в чате.

## 14. Бэкапы и перенос <a name="бэкапы"></a>

### Создать бэкап
```powershell
uv run python -m app.cli backup
```
Создаст `backups/data_YYYYMMDD_HHMM.zip` со всем содержимым папки `data/` (БД + сессия + логи).

### Регулярные бэкапы
Windows Task Scheduler:
- Триггер: ежедневно в 04:00
- Действие: `powershell -Command "cd C:\Users\User\ClaudeC\NexusTG; uv run python -m app.cli backup"`
- (опционально) скрипт ротации — удалить бэкапы старше 14 дней

### Перенос на другой ПК
1. Останови `run.ps1` и `web.ps1` на текущем ПК (Ctrl+C)
2. Заzipни всю папку `NexusTG` целиком (включая `data/`)
3. На новом ПК:
   - Установи Python 3.12+ и uv
   - Распакуй zip в любое место
   - Заполни `.env` (api_id/hash оставь те же, новые не нужны — `tg.session` подхватится)
   - Запусти `setup.ps1` (он не будет логиниться — сессия уже есть)
   - `run.ps1` и `web.ps1`

⚠️ **Не запускай NexusTG параллельно на двух ПК с одной сессией** — Telegram отзовёт обе.

## 15. Стоимость и бюджет токенов <a name="стоимость"></a>

### Модель и ценник
По умолчанию `gemini-2.5-flash`:
- Input: $0.075 за 1M токенов
- Output: $0.30 за 1M токенов

Средний расход на одно сообщение: ~1200 input + ~80 output токенов = ~$0.0001. На 3000 сообщений = ~$0.3.

### Дневной бюджет
`grok_daily_token_budget` в `config.toml` (по умолчанию 8M). Когда превышен — classifier ставится в режим ожидания, новые сообщения копятся в очереди. На следующий календарный день (UTC) счётчик обнуляется.

### Где смотреть
`/health` показывает за сегодня: prompt_tokens, completion_tokens, стоимость в $.

Историю по дням можно вытащить из БД:
```sql
SELECT * FROM grok_usage ORDER BY date DESC;
```

### Как уменьшить расход
- Выключи через `/chats` болтливые чаты, где много нерелевантных захватов
- Если совсем много — переключись на `gemini-2.5-flash-lite` (раз в 4 дешевле, но качество чуть ниже)
- В `config.toml`: `context_window=3` вместо 5 (меньше контекста подгружается)

## 18. Траблшутинг <a name="траблшутинг"></a>

### Web возвращает 500 Internal Server Error
Глянь логи uvicorn в окне `web.ps1`. Чаще всего — синтаксис в шаблоне или SQL ошибка. Перезапусти `web.ps1`.

### Classifier зависает на 429 Too Many Requests
- Если `prepayment credits are depleted` — пополни Gemini billing
- Если просто rate limit — `gemini-2.5-flash` имеет щедрые paid-лимиты; на free-tier (без billing) переключись на `gemini-2.5-flash-lite`

### Дневной бюджет токенов исчерпан
Логи: «Дневной бюджет Grok исчерпан (XXX/YYY токенов)». Подними `grok_daily_token_budget` в `config.toml` ИЛИ подожди до 00:00 UTC.

### `database is locked`
Кто-то ещё пишет в `data/app.db` или `tg.session`. Скорее всего параллельно запущены два экземпляра `run`. Killall:
```powershell
Get-Process python | Stop-Process -Force
```
Потом по одному `run.ps1`, `web.ps1`.

### Сообщения не появляются в инбоксе после захвата
Возможные причины:
- Чат в архиве TG или processing=0 в `/chats`
- Score < 3 + чекбокс «Показать неклассифицированные» снят → отображается только классифицированное
- На задаче стоит action=done/archived/snoozed-active

### Бот не отвечает
- Проверь что `TG_BOT_TOKEN` правильный (можно через https://api.telegram.org/bot<TOKEN>/getMe)
- Проверь что `TG_MY_ID` — твой именно числовой ID, не username
- Проверь что в `run.ps1` лог содержит «TG-бот запущен»
- Если параллельно запущен `cmd_bot` отдельно — может быть конфликт

### Слетели темы / странные классификации
- Возможно правило в `/rules` плохо написано — отключи последнее добавленное и пересмотри
- Сохрани 5-10 хороших примеров через ⭐ — они подмешаются в промт и Gemini «стабилизируется»

### Не приходит код от Telegram
TG присылает код в само приложение Telegram в чат «Telegram». НЕ в SMS (SMS только если у тебя НЕТ ни одной активной сессии). Проверь архив TG.

## 19. Безопасность <a name="безопасность"></a>

### Файл `data/tg.session`
Это **полный доступ** к твоему Telegram-аккаунту от имени приложения. Кто угодно с этим файлом может читать всю твою переписку.
- Хранить только на ПК с Bitlocker или Windows-шифрованием
- Не коммитить в git (есть в `.gitignore`)
- При утере: зайди в TG → Настройки → Конфиденциальность → Активные сессии → Завершить все, кроме текущей
- При переустановке Windows — не забудь сделать `backup` сначала, иначе придётся снова логиниться

### API-ключи
- `XAI_API_KEY` (Gemini): если утёк — отзови на https://aistudio.google.com/apikey и создай новый
- `TG_BOT_TOKEN`: если утёк — `/revoke` у @BotFather

### Сеть
Веб-дашборд слушает на `127.0.0.1:8000` — доступен ТОЛЬКО с твоего ПК. Не выставляй на 0.0.0.0 без авторизации.

## 20. FAQ <a name="faq"></a>

**Q: Можно ли запустить два экземпляра на разных ПК?**
A: Нет. Telegram-сессия может быть активна только в одном месте. Запустишь — TG отзовёт обе сессии и придётся логиниться заново.

**Q: Что будет если выключить ПК?**
A: Ingestion остановится, новые сообщения захватятся при следующем `run` через backfill (если в пределах backfill_days=30 дней). Веб-дашборд просто перестанет отвечать. БД останется целой.

**Q: Можно ли расширить backfill до 90 дней / всех времён?**
A: Да. В `config.toml` поменяй `backfill_days = 90`. Затем сотри `ingest_state` для нужных чатов и запусти `run` заново.

**Q: Как добавить новый чат в обработку, если он только что появился?**
A: Зайди на `/chats` → нажми «🔄 Синхронизировать с Telegram». Новый чат появится. При первом захвате сообщений из него — backfill за последние `backfill_days` дней.

**Q: Сколько примерно стоит месяц использования?**
A: При 100-200 захваченных задач/день и `gemini-2.5-flash` — около $1-3 в месяц.

**Q: Можно ли заменить Gemini на другую модель?**
A: Да. Любая модель с OpenAI-compatible API: OpenAI, Anthropic Claude, локальные через Ollama. Поменяй в `config.toml`: `llm_base_url`, `grok_model`, `llm_input_usd_per_m`, `llm_output_usd_per_m`. В `.env` положи ключ в `XAI_API_KEY` (название поля историческое, на самом деле это просто LLM-ключ).

**Q: Как остановить пайплайн?**
A: Ctrl+C в окне `run.ps1`. Дождись «Остановка по Ctrl+C» — он корректно дописывает данные в БД и закрывает соединения.

**Q: Можно ли отдать веб-дашборд другу?**
A: Технически — пробросить порт через ngrok/Cloudflare Tunnel. Но без авторизации это опасно (любой со ссылкой видит всю твою переписку). Лучше сделать VPN на свой ПК.

**Q: Зачем нужен ±5 контекст вокруг каждой задачи?**
A: Для смысла. Без контекста «Да, согласен» — бессмысленное сообщение. С контекстом ±2 — понятно с чем согласен. Используется при классификации и при просмотре карточки.

**Q: Что делает «ночной consolidator»?**
A: В 03:00 локально автоматически: помечает темы с <3 сообщениями старше 14 дней как hidden; логирует похожие пары тем в файл для возможного merge.
